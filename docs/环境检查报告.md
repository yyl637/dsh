## 三、工具链（含本机已知 Bug 与绕行方案）

### 3.1 Git：可用，但默认命令行报错（重要）

```
$ git --version
git version 2.43.0

$ git config --global --list
error: missing config key GIT_CONFIG_KEY_0
fatal: unable to parse command-line config

$ git init .        # 同样失败
error: missing config key GIT_CONFIG_KEY_0
```

原因：DSH 运行时注入了 `GIT_CONFIG_COUNT=2` 与两个 `GIT_CONFIG_VALUE_*`（用于把 https 的 GitHub 地址改写为 SSH），但缺少配套的 `GIT_CONFIG_KEY_0` / `_1`，Git 解析该注入配置时直接 fatal。

**已验证的绕行方案**（消除注入变量后一切正常）：

```
$ env -u GIT_CONFIG_COUNT git init -q .          → init OK
$ env -u GIT_CONFIG_COUNT git -c user.name=... -c user.email=... commit -qm "probe"  → commit OK
$ env -u GIT_CONFIG_COUNT git log --oneline
f5ffd52 probe commit

$ env -u GIT_CONFIG_COUNT git clone --depth 1 https://github.com/octocat/Hello-World.git /tmp/x
clone exit=0   (README 拉取成功)
```

→ 后续所有 Git 操作我都会加 `env -u GIT_CONFIG_COUNT` 前缀，避免踩坑。全局 `.gitconfig` 不存在，需要时在生产工作区内配置或每次用 `-c` 传参。

### 3.2 Node / npm

```
$ node --version   → v22.22.2
$ npm --version    → 10.9.7
$ pnpm --version   → 已安装
$ yarn             → MISSING（未安装，也不需要）
$ npm config get cache → /home/agentuser/.npm
registry = "https://mirrors.tencentyun.com/npm/"   (来自 ~/.npmrc)
```

**已知 Bug**：npm 缓存/日志目录 `~/.npm` 受沙箱限制**不可写**，导致任何 npm 命令报错：

```
npm error Log files were not written due to an error writing to the directory: /home/agentuser/.npm/_logs
npm error   sudo chown -R 1002:1003 "/home/agentuser/.npm"
```

（该 sudo 建议**无效**，本机无法 sudo，见 §6.2；实际原因是文件沙箱，不是权限位。）

**已验证的绕行方案**：把 cache 指到可写位置。

```
$ npm install --cache /tmp/npmcache is-number@7.0.0
added 1 package in 574ms
$ node -e "require('is-number')('42')"  → true
```

→ 后续统一使用 `npm install --cache <工作区内或 /tmp 缓存目录>`，或直接在项目里写 `.npmrc` 指定 `cache=`。

## 七、限制与需要的额外授权

### 7.1 沙箱与权限

| 限制 | 实测证据 | 影响 |
|---|---|---|
| 只能写工作区（+ 平台临时区） | `~`、`/opt`、`/var/tmp` 写入均 `Permission denied`；`/tmp` 可写 | 不能改 `~/.npm`、`~/.ssh`、`~/.gitconfig`、全局 node_modules |
| 无法提权 | `sudo -n true` → `The "no new privileges" flag is set` | 不能 apt install，不能改系统配置 |
| 全局 node_modules 只读 | `/opt/node/22.22.2/lib/node_modules` → Permission denied | 只能项目内本地安装，不能 `npm i -g` |
| Landlock 部分生效 | 每条命令 stderr 有 `landlock-run: partial enforcement (older Landlock ABI)` | 属正常提示，不影响正常工作区操作 |
| 默认不装大依赖 | 本轮仅在 `/tmp` 装了 `is-number`、`vite@5`、`playwright-core`、`pytest` 用于验证，已清理 | 遵守“不擅自安装/不改配置”要求 |

### 7.2 需要你授权的操作

1. **Git push / 建仓 / 开 Pages** → 提供 GitHub PAT（建议细粒度、仅该仓库、短期），或授权安装 `gh`。
2. **网站部署生成公网地址** → 提供 Vercel/Netlify token，并授权安装对应 CLI。
3. **安装项目依赖**（Vite / React / Playwright 等）→ 首次 scaffold 时执行 `npm install`，属正常开发，但会在工作区产生 `node_modules`（几百 MB 级）；请确认可以。
4. **修改沙箱策略**（如确需写 `~/.npm` 或 `~/.ssh`）→ 需要把会话策略从 workspace-write 放宽到 danger-full-access，会降低隔离性，一般不建议；用 `--cache` 绕行更安全。

### 7.3 未验证能力（不保证）

- GUI 文件卡片的手机端下载行为。
- GUI 是否支持你直接上传 V1.1 源码文件。
